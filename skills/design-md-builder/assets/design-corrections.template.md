# Design corrections

Read this file alongside [DESIGN.md](DESIGN.md) before planning or generating an asset. Entries here are accepted, active instructions. Follow the current user request first; then apply these corrections within their stated scope, ahead of the baseline guide. Consult [design-audit.md](design-audit.md) for unresolved conflicts. Proposals and retired rules in the audit are not active instructions.

To record an explicit instruction for future assets, replace the empty-state sentence below with a uniquely identified entry, using a level-three heading such as `C001: Short rule name` and these fields:

- Scope: Named format or whole brand, including conditions.
- Instruction: Observable action for future assets.
- Overrides: Specific baseline section or earlier correction, or “Adds guidance.”
- Source: User wording or review reference; author and source date only if known.
- Recorded: Actual date this entry was saved.

Keep one-asset edits local and ambiguous interpretations in the audit. Do not expand a scoped instruction to the whole brand. An explicit future instruction supplies approval; do not invent rules from recurring dissatisfaction alone. If you cannot save feedback, return the entry and state that it has not been saved.

Remove or revise an older active entry only when accepted feedback clearly supersedes it, and record the replacement in the audit. When an authorized guide update incorporates a correction into DESIGN.md, remove that active entry and record its destination in the audit. Preserve unrelated entries. Restore the empty-state sentence if no active entries remain. Do not resolve conflicting active rules by date alone. Recording a rule does not prove it has been tested.
